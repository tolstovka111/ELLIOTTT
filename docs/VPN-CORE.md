# Нативное ядро VPN

Приложение не хранит бинарные зависимости в git. Данные через туннель гоняют две
внешние библиотеки:

| Файл | Куда кладётся | Что делает |
|---|---|---|
| `libv2ray.aar` | `android/app/libs/` | Xray-core, собранный gomobile (AndroidLibXrayLite) |
| `libtun2socks.so` | `android/app/src/main/jniLibs/<abi>/` | превращает пакеты TUN в SOCKS-соединения |

## Как подключить

```bash
./scripts/fetch-vpn-core.sh
cd android && ./gradlew assembleDebug
```

Скрипт скачивает `.aar` из релизов AndroidLibXrayLite и достаёт `libtun2socks.so`
из официального APK v2rayNG. Версии фиксируются переменными:

```bash
XRAY_LIB_TAG=v1.8.23 V2RAYNG_TAG=1.9.16 ./scripts/fetch-vpn-core.sh
```

Обе библиотеки распространяются под своими лицензиями (GPL/MPL) — перед выкладкой
сборки пользователям стоит свериться с их условиями.

## Что происходит при сборке

`app/build.gradle.kts` смотрит, лежит ли `app/libs/libv2ray.aar`:

* **лежит** — в компиляцию добавляется набор исходников `app/src/xray/java`
  (`XrayTunnelEngine`), а `BuildConfig.HAS_XRAY_CORE` становится `true`;
* **не лежит** — этот файл вообще не компилируется, и `EngineFactory` отдаёт
  `DemoTunnelEngine`.

Благодаря этому проект собирается в любом окружении, а код движка остаётся
обычным типизированным Kotlin, а не рефлексией по строкам.

## Демо-режим

Без ядра приложение полностью работоспособно как интерфейс: сервис поднимается,
система показывает «ключик» VPN, идёт таймер, работает уведомление. Пакеты из TUN
читаются и отбрасываются — интернет через туннель не пойдёт. На главном экране и в
настройках висит предупреждение, чтобы это нельзя было принять за поломку.

## Путь пакета

```
приложение ──► VpnService.Builder.establish() ──► файловый дескриптор TUN
   │
   └─► Tun2SocksProcess: запускает libtun2socks.so и передаёт ему fd
         через unix-сокет (LocalSocket.setFileDescriptorsForSend)
              │
              └─► SOCKS5 127.0.0.1:10808 ──► Xray-core ──► VLESS-узел
```

Сокеты самого ядра защищены вызовом `VpnService.protect()`, иначе они бы уходили
обратно в туннель и получалась бы петля.

## geoip.dat / geosite.dat

Правила вида `geoip:ru` и `geosite:category-ru` требуют этих файлов рядом с ядром
(`filesDir`). По умолчанию они выключены, а «российские сайты напрямую» работают на
списке доменов, зашитом в `XrayConfigBuilder`. Если положить оба `.dat` в
`filesDir`, можно включить переключатель «Использовать geoip/geosite» в настройках.
